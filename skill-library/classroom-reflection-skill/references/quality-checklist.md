# 质量检查清单

在输出最终结果前，自检以下项目：

## 交互流程

- [ ] 缺少课堂材料时是否先引导上传音频，已有逐字稿时是否接受直接分析？
- [ ] 是否在转写成功且有有效发言后，才询问使用内置标准还是上传自定义评价维度？
- [ ] 是否等待了明确选择，或沿用了用户此前明确给出的选择，而非静默默认？
- [ ] 自定义方式未上传、文件不可读或维度为空时，是否继续等待补充，未回退到内置标准？
- [ ] 选择评价方式是否复用同一案例和转写，未再次运行音频转写？
- [ ] 报告交付后是否主动询问需要根据反馈生成新教案，并等待答复？
- [ ] 仅在用户明确同意并记录 `generate` 后生成教案；选择 `skip` 后是否保留报告并结束本轮？

## 证据化

- [ ] 用户提供自定义评价量规或说“用以下评价量规评价”时，是否仍执行了完整课堂反思流程，而不是只输出评价量规？
- [ ] 是否基于逐字稿，而不是泛泛评价？
- [ ] 所有关键判断是否引用或概括了逐字稿中的具体课堂片段？
- [ ] 是否只评价逐字稿可支持的课堂语言、互动结构、任务组织、学生口头回应和反馈证据？
- [ ] 是否已在内部完成学科识别和评价量规匹配，但用户可见报告只在“基本判断”中简短呈现“学科与量规”，没有单独输出“评价依据”章节？
- [ ] 课堂流程复盘中的环节时间是否同时包含分钟描述和秒数描述，而非只写秒数？
- [ ] 是否先由 `prepare` 确定 `outputRoot`、`outputDir` 和 `publicOutputDir`，而不是手写 skill 目录下的输出路径？
- [ ] 输出文件是否写入 `<output-root>/<lesson-slug>/<conversation-id>/`，且同一案例中的报告、优化教案和教师逐字稿是否复用同一 `outputDir`？
- [ ] 写入前是否已经创建或确认 `<output-root>/<lesson-slug>/<conversation-id>/` 目录？
- [ ] 是否没有把任何产物直接写到 `<output-root>/<lesson-slug>/` 根目录？
- [ ] 面向用户展示时，是否优先使用 `publicReportPath` / `publicLessonPlanPath` / `publicTeacherTranscriptPath`，而不是内部路径？
- [ ] 正文开头是否标注生成时间，且没有把时间戳作为同一案例后续产物的新目录？

## 评价

- [ ] 如果用户提供自定义评价量规，是否注明量规来源为“用户自定义评价量规”？
- [ ] 自定义评价量规是否只替换评价维度和观察重点，而没有省略课堂结构切分、证据化分析和改进建议？
- [ ] 是否给出了分维度定性评价？
- [ ] 内置模式的「定性评价结果」是否先写「师生对话质量」，并分成话语要素与课型、水平占比、重要问答链和四行收束判断？
- [ ] 自定义模式是否保留上传的维度和观察点，没有混入内置标准或强制追加对话质量维度？
- [ ] 引用对话统计时是否使用脚本数字；内置模式是否把指标名放在指标列、数字放在本节课列？
- [ ] 报告里是否没有出现「固定追加维度」「必须原样引用」「不要重算」这类写作说明？
- [ ] 内置模式的提问、回答、理答是否各有一张水平占比表，每级有含义、大约次数和一句原话？
- [ ] 内置模式是否写出 1–2 条带时间的重要问答链，包含提问、回答、理答原话？
- [ ] 每个维度是否有判断依据？
- [ ] 是否没有输出百分制分数、单项得分或排名百分位？
- [ ] 定性表现判断是否与证据一致，不虚高？
- [ ] 自定义量规中无法听证的观察点是否保留在“证据不足的维度”，注明“证据不足，暂不评价”及所需补充材料，而非删除、替换或据此作负面评价？

## 问题与建议

- [ ] 每个关键问题是否有证据、影响和修改方向？
- [ ] 建议是否具体到课堂环节和教师语言？
- [ ] 是否避免只说"加强互动""突出学生主体"等空话？
- [ ] 修改建议是否说明了"哪个环节、原表现、怎么改、为什么改、预期效果"？

## 可替换语言

- [ ] 可替换课堂语言是否自然，适合真实课堂？
- [ ] 是否避免过度书面化？
- [ ] 是否覆盖了导入语、提问语、追问语、评价语、总结语中的关键问题？

## 教案重构（报告交付后，用户明确同意时）

- [ ] 教学目标是否采用核心素养导向，而不是“三维目标”框架？
- [ ] 是否先按学段和学科查阅 `references/core-literacy-map.json`，并只使用 `verificationStatus: "standard_declared"` 的核心素养条目？
- [ ] 同一学科同时存在义务教育和普通高中条目时，是否先根据年级/学段确定 `stage`，避免错用另一学段核心素养？
- [ ] 匹配条目存在 `developmentalDimensions` 时，是否按小学/初中等阶段选用了对应二级维度，避免跨阶段混用？
- [ ] 是否避免把 `interpretationSources` 中的解读材料当作核心素养本身的来源？
- [ ] 是否参考已匹配条目的 `objectiveWritingHints` 来组织目标表述，而不是只拼接核心素养名称？
- [ ] 命中已核验学科时，每条教学目标是否同时包含“目标表述”和“对应核心素养”？
- [ ] 未命中已核验学段/学科条目时，是否只把中国学生发展核心素养总体框架作为通用育人参照，并提示需按对应学段、对应学科课程标准人工核对？
- [ ] 教学目标是否落在可观察的学习表现上，而不是空泛口号？
- [ ] 是否体现了问题链、学生活动和评价证据？
- [ ] 每项主要改动是否对应报告中的反馈与所选维度，而非另起炉灶？
- [ ] 是否保留了原课堂中有价值的部分？
- [ ] 教案是否可在真实课堂中实施？

## 教师逐字稿生成（仅在用户要求时）

- [ ] 是否基于优化版教案生成，而不是脱离教案另写一节课？
- [ ] 是否输出为教师易读的 Markdown，而不是 JSON 或复杂数据结构？
- [ ] 是否明确标注为拟用教师上课逐字稿，避免写成真实课堂实录？
- [ ] 是否按教学环节展开，并只标注环节级大致时长，而不是秒级时间轴？
- [ ] 是否覆盖每个主要教学环节，并包含教师怎么说、学生可能怎么答/做、课堂提醒？
- [ ] 关键问题是否配有追问或支架语？
- [ ] 形成性评价语言是否具体指向学生表现，而不是只写"很好""不错"？
- [ ] 教师语言是否自然可说，适合真实课堂试讲和上课？
- [ ] 板书、课件切换、等待、讨论等课堂提示是否清楚，且与教案一致？

## 边界守则

- [ ] 不基于文本以外（视频动作、语调、表情）做断言。
- [ ] 不对教师做主观负评，语气专业建设性。
- [ ] 不预测学生成绩。
- [ ] 逐字稿无法判断的现场或画面细节没有作为评价结论输出。
