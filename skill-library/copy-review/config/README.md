# 单位规范配置说明

## 这是什么

`config/org-rules.md` 是"单位硬性要求"文件，用于把**你所在单位对稿件的硬性要求**配置为审稿的最高准则。

生效逻辑：

- 审稿时（Step 1）检查 `org-rules.md`：只要填入了实际内容，就逐条作为判定标尺
- 单位要求与通用规则（`references/` 下各规范）冲突时，**一律以单位要求为准**
- 未配置时，skill 按通用规则正常审稿，不受影响

## 方式一：让 AI 配置

适用：手里有现成的单位制度文件、格式规范、审稿要点，不想自己整理。

1. 把单位的制度文件、格式要求或审稿要点**直接粘贴在对话中**（或上传文件）
2. 说一句：**"帮我配置到 copy-review 的单位规范"**
3. AI 会做三件事：
   - 通读材料，提炼出**可判定的硬性要求**（剔掉空话，只留能逐条核对的内容）
   - 按 `org-rules.md` 的六个维度归类整理
   - 写入本文件；若已有内容，保留原条目、合并去重，冲突处以你最新提供的为准

## 方式二：手动配置

适用：想自己控制内容，或只需改一两处。

1. 用任意编辑器打开 `config/org-rules.md`
2. 删除文件中的 `<!-- 示例 -->` 注释块和示例条目
3. 按维度填写，每条一行，以 `- ` 开头：
   - 一、文种与场合要求：单位特有的文种写法、结构约定
   - 二、人名、职务与排序规则：领导排序、职务称法
   - 三、必写 / 禁写要素：必须出现的内容、严禁出现的内容
   - 四、禁用词与敏感表述：禁用的词、需淡化的表述
   - 五、格式硬性规范：字体、字号、层级、缩进、落款
   - 六、其他硬性要求：流程性、审核性要求等
4. 保存文件，审稿自动生效

## 编写指南（两种方式都适用）

**每条要求必须"具体、可判定"**——审稿时是按条目逐条核对原文的：

| 判定标准 | 写法 |
|---|---|
| ✅ 可判定 | "领导排序：党委书记、院长、党委副书记、副院长（主持工作）" |
| ✅ 可判定 | "征稿预告必须注明'稿件需经原创性与 AIGC 校验'" |
| ❌ 不可判定 | "注意领导顺序" |
| ❌ 不可判定 | "行文要规范一些" |

其他要点：

- **反向要求同样有效**：写"禁写"条目（如"禁止打包票"），审稿命中即报严重问题
- **冲突处理**：单位要求与通用规则冲突时以单位要求为准，报告中会注明"该条按单位要求判定"
- **更新维护**：制度变化时直接改文件，或把新文件发给 AI 让它合并更新
- **备份**：重要版本可另存一份副本，避免误改

## 如何确认配置已生效

审稿报告的"整体判断"板块有 **单位规范符合性** 一行：

- 显示"已逐条核对，N 项达标 / M 项违反" → 配置已生效
- 显示"未配置单位规范" → `org-rules.md` 尚未填写内容，按通用规则审稿
