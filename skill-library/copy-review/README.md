# copy-review 文案审稿 Skill

一个用于**审校大学生文案写作**的 AI 审稿 skill，实习生与工作新手同样适用。它把审稿经验沉淀为可复用的流程：按八大通病逐项诊断，输出**分级问题清单 + 修改建议 + 全文修订稿**，并支持事实核查与单位硬性要求配置。

> 适用对象：大学生（校园新闻稿、活动预告、比赛公示、主持词、课程文案等）、实习生/职场新手（通知、总结、汇报材料、宣传稿、微信推文等）。
> 不适用：纯数据表格核对、代码评审、无文本内容的图片。

## 二、核心逻辑

### 八大通病（诊断维度）

| # | 通病 | 一句话说明 |
|---|------|-----------|
| 一 | 模糊场合、不分场景 | 一套腔调套用所有文种 |
| 二 | 只顾行文、不讲逻辑 | 断句碎、缺过渡、因果倒置、流水账 |
| 三 | 不做调研、一想当然 | 数据无出处、信息缺口不补查 |
| 四 | 用词粗放、表述不准 | 近义词混用、职务称谓不准、口语未转书面语 |
| 五 | 照搬机器、一眼戳穿 | AI 痕迹：Markdown 残留、套话、模板腔 |
| 六 | 排版混乱、可读性差 | 一逗到底、段落不分、层级错乱 |
| 七 | 空话泛滥、语言赘余 | 套话灌水、信息密度低 |
| 八 | 只见树木、不见森林 | 局部优美、整体失焦 |

### 审稿工作流（八步）

1. **定场合** → 识别文种，加载对应规范；若有单位配置则加载为最高准则
2. **通读抓整体** → 先见森林：主题唯一、结构完整、主线清晰
3. **八维诊断** → 逐条通病排查，每条问题引用原文；疑似 AI 先跑脚本快筛再人工定性
4. **证据与分级** → 原文引用 + 通病类别 + 严重度（严重/中等/轻微）
5. **事实核查（交互）** → 列出待核查清单，**询问调用者**是否全网核查；不核查则保留"待核查"标注
6. **修改建议** → 每条问题给"病因 + 改法 + 改写示范"
7. **输出审稿报告** → 总评 + 分级清单 + 事实核查 + 亮点保留
8. **产出修订稿** → 全文修订版 + 改动对照说明

### 三个特色机制

- **口径与分寸审查（Step 3.5）**：正式材料先过"表述是否过满、是否越级、口径是否需核对"的关，再谈文采；只列风险、不代下结论
- **事实核查分支**：审稿中自动汇总待核查内容（数据/人名/政策表述），由你决定是否执行全网核查，结果以"属实/失实/存疑/无法核实"四态写入报告
- **单位硬性要求（最高准则）**：可把你单位的稿件硬性要求配置为最高准则，与通用规则冲突时以单位要求为准

## 三、安装方法

> 安装原理各 Agent 一致：把 `copy-review` 文件夹（内含 SKILL.md）放到对应 Agent 的 skills 目录即可。下面**以 WorkBuddy 为例**详细说明，Codex、Claude Code 等常用 Agent 的安装见文末。

### 以 WorkBuddy 为例

1. 获取 `copy-review.zip`（分发包），解压出 `copy-review/` 文件夹
2. 放入 skills 目录（二选一）：
   - **用户级**（所有项目可用，推荐）：`~/.workbuddy/skills/copy-review/`
     - Windows 示例：`C:\Users\你的用户名\.workbuddy\skills\copy-review\`
     - macOS/Linux 示例：`/Users/你的用户名/.workbuddy/skills/copy-review/`
   - **项目级**（仅当前项目共享）：`.workbuddy/skills/copy-review/`
3. 重启或刷新 WorkBuddy，使 skill 被识别
4. 验证：对话中发送"审校一下这篇新闻稿，看看有什么问题"——若按八大通病输出报告，说明安装成功

### OpenAI Codex（CLI / IDE）

1. 解压出 `copy-review/` 文件夹
2. 放入用户级 skills 目录：`~/.codex/skills/copy-review/`
   - 新版 Codex（采用 Agent Skills 规范）使用 `~/.agents/skills/copy-review/`，项目级为 `.agents/skills/`
   - 仅当前项目共享：`.codex/skills/copy-review/`（或 `.agents/skills/copy-review/`）
3. 重启 Codex；用 `/skills` 查看已加载技能，或直接描述任务触发（如"审校这篇新闻稿"）
4. 临时方案（不装目录也可用）：`codex --instructions ./copy-review/SKILL.md`，或把 SKILL.md 内容直接粘贴给 Codex

### Claude Code（CLI / IDE）

1. 解压出 `copy-review/` 文件夹
2. 放入用户级目录：`~/.claude/skills/copy-review/`（自动发现，无需重启）；仅当前项目：`.claude/skills/copy-review/`
3. 直接说"用 copy-review 审校这篇新闻稿"即触发

### 其他 Agent（通用指引）

- 若 Agent 遵循 **Agent Skills 规范**（大多数较新的 Agent 均支持），一般可放入用户级 `~/.agents/skills/` 或项目级 `.agents/skills/` 目录
- 若 Agent 不支持 skills 目录，可用**临时方案**：把 `SKILL.md` 内容粘贴到对话中，或通过指令参数加载（如 Codex 的 `codex --instructions SKILL.md`）
- 不确定时，查该 Agent 官方文档中的 "skills" / "instructions" 配置说明，找到 skills 目录后放入即可

## 四、调用方法

直接以自然语言发起请求即可，无需任何命令。触发词：**审校、批改、指出问题、提修改意见、润色改稿、审稿**。

示例：

- "用 copy-review 审一下这篇活动预告"（附文稿）
- "帮我批改这份工作总结，重点看逻辑和空话"
- "审这篇新闻稿，并执行事实核查"（触发核查分支）
- "这篇文章是不是 AI 写的？帮我查一下"（触发 AI 痕迹检测）

审稿时会自动产出两份交付物：**审稿报告**（问题清单+建议+示范）与**全文修订稿**（改动对照说明）。

## 五、可选配置：单位硬性要求

想让审稿贴合你单位的特殊要求（格式规范、领导排序惯例、必写/禁写要素、禁用词），两种方式：

1. **让 AI 配置**：把单位的制度文件/格式要求粘贴到对话中，说"配置到 copy-review 的单位规范"
2. **手动配置**：直接编辑 `config/org-rules.md`，按模板填写（详见 `config/README.md`）

配置后审稿自动生效，作为最高准则逐条核对。
