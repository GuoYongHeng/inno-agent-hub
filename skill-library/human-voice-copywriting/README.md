# 活人感文案

把公文腔、品牌腔、AI 腔的中文文案，改写成像一个真人在对一个真人说话。

一个 [Claude Code](https://claude.com/claude-code) skill，外加一个不依赖任何模型、离线可跑的中文文案体检 CLI。

---

## 它从哪来

一张工厂门口的手写通知：

> 假期到了，有些员工带小孩来工厂，不准带到车间，容易发生事故。全部到人事处做好登记，全部在一楼饭堂玩耍，管理饭堂有空调。有电视看。小孩登记后，这两个月可以免费在饭堂吃饭。
>
> 第二，所有员工知悉，不准在荔新公路开车逆行，多开几分钟去调头。不要拿自己生命开玩笑。门口泥头车太多，要小心再小心。

没有排版，没有公文用语，语序和标点都不讲究。但它比"请广大员工提高安全意识，共同守护生命安全"有效得多。

差的不是文笔，是**信息**：门口、泥头车、太多、一楼饭堂、有电视、这两个月。

这个仓库把这件事拆成了可执行的判据、公式和一个能跑的检测器。

## 核心

> 人感 = 具体信息密度 × 对象感 × 真诚。三项任一为零，整段归零。

抽象词的本质是提纯——把场景、温度、生活痕迹滤掉，只留一个正确但空洞的结论。把被滤掉的东西装回去，人感自动出现。**只调语气不加信息，得到的是油腻，不是人感**：把"请勿吸烟"改成"宝子们别抽烟啦"没有变得更像人，只是变得更难看。

### 三条判据

| 判据 | 怎么做 | 不过关意味着 |
|---|---|---|
| 去名测试 | 删掉品牌 / 主体名，这句话还剩多少信息 | 剩零 = 包装语 |
| 证伪测试 | 这句话能被验证或推翻吗 | 不可证伪 = 不可信 |
| 念出声测试 | 能对着一个具体的人念出来而不尴尬吗 | 尴尬 = 广播腔或假亲昵 |

"匠心品质"过不了证伪测试，"每一颗都要过三遍手"能过。

### 一个公式

**场景细节 + 行动指令 + 情绪锚点**

> 欢迎携带宠物入店。
> → 如果它一路闻了很多树，没关系，我们等它闻完。

场景是进店前的犹豫，行动是消除时间压力，情绪落在**我方承担了什么成本**——而不是"我方多热情"。

三层必须全真：细节来自真实观察，指令解决真实阻力，情绪对应真实感受。任何一层表演，整个结构都会塌。

## 装

**Claude Code**

```bash
git clone https://github.com/Zhanglala103838/human-voice-copywriting.git \
  ~/.claude/skills/human-voice-copywriting
```

然后正常说话就行——"帮我把这条停电通知写得有人味一点""这段太 AI 了"，skill 会自己触发。

**别的模型**

把 `SKILL.md` 贴进系统提示，需要细节时再喂 `references/` 里对应的那个文件。它们是纯 Markdown，没有任何 Claude 专属语法。

**只要那个 CLI**

不需要模型，不需要联网，Python 3 标准库跑：

```bash
python3 scripts/check_copy.py draft.md
python3 scripts/check_copy.py --list      # 看全部检测规则
cat draft.md | python3 scripts/check_copy.py -
```

## CLI 长什么样

六类检测（说教越界 / 故作亲昵 / 抽象套话 / 公文腔 / AI 腔 / 空承诺）＋四项指标（具体度 / 对象感 / 感叹号 / 句长）。命中处不只报错，还给出对应的追问：

```
PREACH  说教与共情越界（3 处）
  为什么是问题：在评价对方的处境，而不是描述它。品牌挪用当事人的自嘲即消费苦难。
  改写时先回答：这句话是在描述对方的处境，还是在评价对方的处境？
    L7    「你还年轻」  ← 有人说五仁月饼不好吃，我们认为：那是因为你还年轻…
    L7    「生活的毒打」  ← 有人说五仁月饼不好吃，我们认为：那是因为你还年轻…

!!  具体度      每百字 0.0 个可拍摄信号（数字/单位/时间/实物名词）  参考线 >= 1.5
!!  对象感      你/您/自己/各位 2 次 vs 我们/本公司 3 次  目标 前者 >= 后者且不为 0

[结论] 重写。命中说教/假亲昵红线 5 处——这类问题改词没用，动机不对。
```

**它给的是提示，不是判决。** 词表能抓到堆料，抓不到"每句都正确、就是没有现场和对方"的观点陈述——那类只能靠三条判据人工过。脚本每次都会把三条判据打印在结论后面，就是这个原因。

`examples/` 里有四个校准样本，`./examples/run.sh` 一次跑完。第一版脚本把工厂通知母本判成了"需要大改"，所以它现在留在回归集第一位。

## 什么时候别用它

法律条款、合规声明、金融风险提示、药品剂量与禁忌、安全操作强制项、事故定责——这些地方要精确不要温度，"有人味"会削弱效力甚至制造风险。

正确做法是分层：**条款正文保持精确，在它前后加一段人话**解释"这对你意味着什么、你现在该做什么"。
