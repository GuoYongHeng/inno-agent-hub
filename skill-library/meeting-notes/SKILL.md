# 会议纪要整理

帮用户把混乱的原始素材(语音转写稿、群聊记录、潦草笔记)整理成可以直接发群的纪要。

## 好纪要的唯一标准

发到群里之后,**没开会的人能照着执行,开过会的人不用再翻聊天记录**。所以重点不是"记全",而是把三类东西拎出来:定了什么、谁在什么时间前做什么、还有什么事没定。

## 工作流程

1. **通读原始素材**,区分三类信息:决策、待办、讨论(没有结论的)。
2. **按标准结构输出**(见下)。
3. **待办逐条核对**:每条必须落到"谁 + 做什么 + 什么时候"。原始素材里缺负责人或缺截止时间的,先从上下文推断;推不出来就标注"待确认",不要编。
4. 长会议(>1 小时或原文 >3000 字)在纪要开头加一段"30 秒速览"。

## 输出结构

```
【一句话结论】这次会议最重要的一件事(给没来的人)

一、决定事项
1. …(相关背景一句带过)

二、待办事项
| 事项 | 负责人 | 截止时间 | 状态 |
|------|--------|----------|------|

三、遗留问题(讨论了但没结论的,写清卡在哪、下一步谁推动)

四、关键讨论(可选,只保留影响理解的分歧点;没有就删掉这一节)
```

**一句话结论是纪要的灵魂**。判断标准:领导只看这一行,能不能知道这个会开得值不值。

## 整理技巧

- **口语翻译**:转写稿里的"我觉得吧、那个、就是说"全删;"A 说应该这样、B 说不行"翻译成"关于 X 存在分歧:A 主张 …,B 担忧 …"。
- **识别伪决策**:会上说"那就先这样吧""回头再说"不是决策,放遗留问题,别写进决定事项——把伪决策写成决议是纪要最大的事故。
- **待办动词要具体**:"跟进一下"→"XX 向 A 索取接口文档";"优化一下"→"输出 v2 方案并标注改动点"。
- **数字和名字逐一核对**:转写稿常见同音字错误("张伟/张伟伟""第三季度/第二季度"),有歧义的地方标注"(原文不清,请确认)"。
- 不确定归属的发言不要归错人——写"与会者"或标注待确认,归错人比漏记严重。

## 示例

输入(转写稿节选):"嗯…那个新版本我们还是定在下上吧,14号,王强那边UI能不能赶上就看他的了,然后服务器这个事小李你去问问采购,预算应该没问题吧回头找财务确认下,还有上次说的那个客服系统,大家觉得要不先缓缓,等Q4…"

输出(节选):

```
【一句话结论】新版本定档 14 号发布,服务器采购和客服系统两件事有了初步方向。

一、决定事项
1. 新版本定于 14 日发布
2. 客服系统项目暂缓至 Q4 再评估

二、待办事项
| 事项 | 负责人 | 截止时间 | 状态 |
|------|--------|----------|------|
| UI 稿交付(决定 14 号能否发布的关键) | 王强 | 待确认 | 待确认 |
| 向采购询问服务器报价 | 小李 | 待确认 | 进行中 |
| 服务器预算向财务确认 | 小李(推断) | 待确认 | 待确认 |

三、遗留问题
1. 服务器预算上限未明确——会议中未给出结论,需小李与财务确认后同步
2. UI 是否能赶上 14 号未确认——建议周一主动确认,若延期需尽早调整发布计划

四、关键讨论
无(会议未出现明显分歧)。
```

注意:三处"待确认"都没有编造;王强的截止时间其实隐含在"14 号发布"里,但依赖关系复杂,标待确认并在遗留问题里给出兜底动作。

## 自检清单

- [ ] 一句话结论能让没开会的人看懂会议价值
- [ ] 每条待办有负责人;缺的标"待确认",没有编造
- [ ] 伪决策("先这样""回头再说")没有被写成决议
- [ ] 人名、数字、日期与原文核对过,歧义处已标注
- [ ] 没有口语残留("嗯""那个""就是说")

---

**语言要求**：默认使用简体中文输出；用户明确指定其他语言时以用户指令为准。
